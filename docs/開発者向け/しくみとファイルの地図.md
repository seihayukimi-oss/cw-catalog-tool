# しくみとファイルの地図

## しくみ

中身（HTML＋JavaScript）は1つで、器が2つです。

- **アプリ版**（Tauri 2・ポータブル版 `CWCatalog.exe`）：画面は Windows の WebView2。ネットの読み込み・ファイルの書き込み・更新は Rust の側で行う
- **HTML版**（`cw-catalog.html` の1ファイル）：Chrome・Edge で開くだけ。GitHub Pages にも置く（開くたびに最新）

```
共用カタログ（index.json・index-r18.json・meta.json）── 読むだけ ──▶ CWカタログ
                                                                  │ 選んでDL → 中身を確かめる
                                                                  ▼
                                    CardWirth（1.50／Next／Py）の Scenario・素材・スキンの置き場所
```

- 共用カタログの登録・管理・通報は、別のリポジトリ [seihayukimi-oss/cardwirth-catalog](https://github.com/seihayukimi-oss/cardwirth-catalog) です（[共用カタログの運用.md](共用カタログの運用.md)）
- カタログ・ツールの記録の形は [データ形式.md](データ形式.md)（公開の仕様）

## ファイルの地図

| 場所 | 中身 |
|---|---|
| `src/core/` | 画面に関係ない中身（zip・cab・lzh・7z の展開、Summary.wsm／Summary.xml の読み取り、文字コード、カタログ、インストール）。HTML版・アプリ版で共通 |
| `src/app/` | 画面（catalog-view.js・download.js・changelog-view.js など） |
| `src/platform/` | 器ごとの違い：`tauri.js`（アプリ版）・`fsa.js`（ブラウザのフォルダ書き込み）・`browser.js`（HTML版） |
| `src/entry-tauri.js`・`src/entry-web.js` | アプリ版・HTML版の入口 |
| `src-tauri/` | アプリ版の器（Rust・Tauri 2）：ポータブル版の土台・ネットの読み込み・更新・ダウンロードフォルダ・Windowsへの登録 |
| `build.mjs` | 組み立て（`npm run build`）。CHANGELOG.md もアプリの中に入れる |
| `test/` | 試験（`core.test.mjs`。`e2e.mjs` は実物のシナリオが要る） |
| `package/はじめに.txt` | 配布物に入れる説明 |
| `scripts/make-portable.mjs` | 配布物（zip・latest-portable.json）を作る |
| `scripts/third-party.mjs` | 使っている部品の一覧と、部品の許諾文（THIRD-PARTY-NOTICES.txt）を作る |
| `scripts/strings/listall.mjs` | 画面の文の一覧を作る |
| `CHANGELOG.md` | 更新履歴（アプリの「設定」のいちばん下にも出る） |
| `SECURITY.md` | 安全の報告の受け方 |
| `docs/開発者向け/` | このファイル・[引き継ぎガイド.md](引き継ぎガイド.md)・[データ形式.md](データ形式.md)・[共用カタログの運用.md](共用カタログの運用.md) |
| `docs/みんな向け/` | [使っている部品.md](../みんな向け/使っている部品.md)（自動で作る）・[お知らせ.md](../みんな向け/お知らせ.md) |
