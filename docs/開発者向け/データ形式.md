# CWカタログ データ形式（format 1）

CWカタログのツールが読み書きするデータの仕様です。誰でも自由に使えます（MIT）。
WebCardWirthなど、他のツールやサイトからカタログを読み込んだり、手持ちの記録をやりとりしたりするのに使えます。

- **カタログ**：作品の「配布場所の住所録」。ネットに公開して、ツールが読む
- **ツールの記録**：利用者の手元にある作品の一覧（版・タグ・メモなど）
- **シナリオの判定方法**：ファイルを開かずに、形式・版・作者を知る方法

文字コードはすべて UTF-8、日付は `YYYY-MM-DD`、日時は ISO 8601（UTC）です。

---

## 1. カタログ

### 公開のしかた

| ファイル | 中身 |
|---|---|
| `meta.json` | 小さい要約。ツールはまずこれだけを取りに行く |
| `index.json` | カタログ本体 |

GitHub Pages に置くと、どのサイトのJavaScriptからでも読めます（`Access-Control-Allow-Origin: *` が付くため）。

```
https://<アカウント>.github.io/<リポジトリ>/meta.json
https://<アカウント>.github.io/<リポジトリ>/index.json
```

### meta.json

```json
{
  "format": 1,
  "generated": "2026-11-01T12:00:00Z",
  "count": 128,
  "sha256": "index.json の中身の SHA-256（16進）",
  "commit": "このカタログを作ったコミット（40桁の16進。あれば）",
  "mirrors": ["https://cdn.jsdelivr.net/gh/<アカウント>/<リポジトリ>@<commit>/index.json"]
}
```

ツールは前回の `sha256` と比べて、変わっていたときだけ `index.json` を取り直します。

`r18`（任意・ツール 0.4.1 から）は、R18 の作品だけを分けたファイル（`index-r18.json`。中身は `index.json` と同じ形）の `{ "sha256": "…", "mirrors": [ … ] }` です。ツールは、設定で R18 をONにした人だけ、写し → `index.json` と同じ場所の `index-r18.json` の順に取り、指紋が合ったときだけ使います。そのファイルの作品は、`rating` を書き忘れていても R18 として扱います。

`mirrors`（任意・ツール 0.4.0 から）は、`index.json` の写しのURLです。ツールは先に写しから取り、中身の SHA-256 が `sha256` と合ったときだけ使います（合わなければ、`meta.json` と同じ場所の `index.json` を取ります）。使える写しは https の `cdn.jsdelivr.net/gh/`・`fastly.jsdelivr.net/gh/`・`*.github.io`・`raw.githubusercontent.com` だけで、最大3つです。コミットを固定したURLにすると、写しが古いまま残ることがありません。

### index.json

```json
{
  "format": 1,
  "engines": [ … ],
  "authors": { "<GitHubアカウント>": { … } },
  "entries": [ { … }, { … } ]
}
```

| キー | 型 | 説明 |
|---|---|---|
| `format` | 数値 | 形式の版。**この文書は 1**。知らない値なら読まずにエラーにすること |
| `engines` | 配列 | 対応エンジンの一覧（下記） |
| `authors` | オブジェクト | 作者さんの情報。キーはGitHubアカウント |
| `entries` | 配列 | 作品の一覧 |
| `attribution` | オブジェクト | 任意。出典（このカタログを作ったところ）。`name` と、任意で `url`。写して使う人に、元のカタログとして表示してもらうため |
| `license` | 文字列 | 任意。データの決まり（例：`CC0-1.0`） |
| `content_labels` | 配列 | 任意。注意のラベルの種類を増やす（管理人用）。`{ "id": "utsu", "name": "鬱・救いのない展開" }` のように。`id` は英小文字・数字・`_`・`-`（30文字まで）。同じ `id` なら名前を上書き |
| `links` | オブジェクト | 任意。`register`（登録フォーム）・`manage`（直す・登録解除）・`report`（通報）のURL |

#### engines[]

```json
{ "id": "next", "name": "CardWirthNext 1.60", "formats": ["classic", "next"], "scenario_dir": "Scenario" }
```

| id | エンジン | 遊べる形式 |
|---|---|---|
| `cw150` | CardWirth 1.50（1.28以下の作品もここに含める） | classic |
| `next` | CardWirthNext 1.60 | classic, next |
| `py` | CardWirthPy | classic, wsn |

#### authors{}

| キー | 型 | 説明 |
|---|---|---|
| `owner` | 文字列 | GitHubアカウント |
| `names` | 文字列の配列 | 作者名（複数の名義を持てる） |
| `readme_url` | 文字列（任意） | 作者さん共通のReadme（規約）の `.txt` |
| `site` | 文字列（任意） | 作者さんのサイト |

#### entries[]（作品1件）

```json
{
  "id": "e00012",
  "owner": "example-author",
  "type": "scenario",
  "name": "サンプルの森",
  "author": "見本作者",
  "version": "1.10",
  "updated": "2026-11-01",
  "format": "classic",
  "wsn_version": null,
  "compat": { "cw150": "verified", "next": "verified", "py": "expected" },
  "convert": "self",
  "downloads": [
    { "label": "GitHub Releases", "url": "https://…/sample_v1.10.zip", "kind": "direct", "status": "active" },
    { "label": "作者サイト", "url": "https://…/dl.html", "kind": "page", "status": "mirror", "note": "DLキーはReadme参照" },
    { "label": "uploader.jp", "url": "https://…/download/1", "kind": "page", "status": "closed", "until": "2026-11-25" }
  ],
  "file": { "name": "sample_v1.10.zip", "sha256": "…64桁…" },
  "readme": "りどみ.txt",
  "level": { "min": 1, "max": 3 },
  "tags": ["探索", "短編"],
  "description": "紹介文",
  "requires": [],
  "related": ["e00013"],
  "links": ["https://…（徒然亭などの登録ページ）"],
  "intro": [
    { "url": "https://…（作者さんの紹介ページ）" },
    { "url": "https://misskey.io/notes/…", "label": "告知" }
  ]
}
```

| キー | 必須 | 型 | 説明 |
|---|---|---|---|
| `id` | ◯ | 文字列 | `e` ＋ 5桁以上の数字（共用カタログ）、または `p` ＋ 5桁以上の数字（個人用カタログ）。カタログ内で一意 |
| `owner` | ◯ | 文字列 | 登録したGitHubアカウント |
| `type` | ◯ | 文字列 | `scenario` `skin` `variant` `mod` `material` `resource` `other` |
| `name` | ◯ | 文字列 | 作品名 |
| `author` | ◯ | 文字列 | 表示用の作者名 |
| `version` | ◯ | 文字列 | 最新の版。比べ方は「版の比べ方」を参照 |
| `updated` |  | 日付 | 公開日・更新日 |
| `format` | ◯ | 文字列 | `classic`（1.50以前）／`next`（Next 1.60・データ版7）／`wsn`（Py）／`none`（シナリオ以外） |
| `wsn_version` |  | 数値か null | `format` が `wsn` のときの版（Wsn.5 なら 5） |
| `compat` | ◯ | オブジェクト | `cw150` `next` `py` それぞれ `verified`（確認済み）・`expected`（動くはず）・`no`（動かない）・`unknown`（未確認） |
| `convert` | ◯ | 文字列 | 他の形式への変換：`allowed`（自由）・`self`（自己責任ならOK）・`forbidden`（しないでほしい）。**変換したものの再配布は、どの値でも不可** |
| `downloads` | ◯ | 配列 | 配布元。**上から順に優先**。下表 |
| `file` |  | オブジェクト | 配布ファイルの `name` と `sha256`（手動DLしたファイルの照合用） |
| `readme` |  | 文字列 | zip内のReadmeのファイル名 |
| `level` |  | オブジェクト | 対象レベル `min` `max` |
| `tags` |  | 文字列の配列 | タグ |
| `claim` |  | 文字列 | 登録した人。`author`＝作者さん本人（サイト認証済みを含む）／`proxy`＝作者さん以外の代理登録。登録フォームが付ける |
| `labels` |  | 文字列の配列 | 分類名（作者さんごと・企画ごとなどの分け方。画面では「分類名」と呼ぶ）。DL一覧を書き出すときに、利用者が選んだフォルダの名前が入る。受け取った人は、取り込むかどうか・どの分類名を取り込むかを選べる |
| `description` |  | 文字列 | 紹介文 |
| `rating` |  | 文字列 | 対象年齢。`all`（全年齢・省略時）／`r15`／`r18`。ツールは R18 をいつもは表示せず、設定でONにした人（初回だけ年齢確認）にだけ出す。R18 の作品は、アプリの中ではダウンロードせず、配布元をブラウザで開く |
| `content` |  | 文字列の配列 | 注意のラベル。最初からあるのは `gore`（グロ・残酷描写）・`horror`（ホラー）・`sexual`（性的な表現・R15相当）。カタログの `content_labels` で増やせる。利用者は「特定のラベルを持つ作品を非表示にする」を選べる |
| `state` |  | 文字列 | 共用カタログでの状態。`public`（公開中・省略時）／`held`（一時保留中。通報が多かったものなど）。ツールは、一時保留中の作品をいつもは出さず、「一時保留中の作品を表示」で選んで取れる。承認待ち・非公開・登録解除したものは、そもそも `index.json` に入れない |
| `held_reason` |  | 文字列 | 一時保留中の理由（あれば） |
| `site` |  | URL | 作者さんのサイト |
| `checked` |  | 文字列 | 載せた人が、どこで確かめたか。`readme`／`site`（作者公式サイト・配布ページ）／`author`（作者本人へ直接確認）／`other` |
| `checked_note` |  | 文字列 | その補足 |
| `derivative` |  | オブジェクト | 改変版のとき。`of`（もとの作品）と `basis`（改変してよいと分かるもの。規約のURLなど） |
| `origin` |  | オブジェクト | ほかのカタログから写したときの、元のカタログ。`name` と、任意で `url`。ツールは「出典」として表示する |
| `requires` |  | IDの配列 | ファイルとして必要な作品（MODの元シナリオなど） |
| `related` |  | IDの配列 | 関連作品（続編・前作など。ファイルは独立） |
| `links` |  | URLの配列 | 他の登録ページ |
| `intro` |  | 配列 | 紹介ページ（作者さんのサイト・X・Misskeyなど）。`url` と、任意で `label`。最大10件。ツールはDLの前に、ページの題名・説明・画像（OGP）を見せる |

#### downloads[]（配布元）

| キー | 必須 | 説明 |
|---|---|---|
| `url` | ◯ | `https://` か `http://` |
| `kind` | ◯ | `direct`＝URLを開くとファイルが落ちる／`page`＝ページを開いて手動でDL（DLキー・同意・ログインなど）／`list`＝ファイル一覧のページ（アップローダーなど）。更新チェックのとき、作品名（または `match`）に合うファイルのうち版がいちばん新しいものを探す |
| `match` |  | `list` のとき、一覧で探す名前（空なら作品名） |
| `status` | ◯ | `active`＝現役／`mirror`＝予備／`old`＝旧・移転済み（まだ見られる）／`closed`＝終了・終了予定 |
| `until` |  | `closed` のときの終了日 |
| `label` |  | 表示名 |
| `note` |  | 補足（DLキーの案内など） |
| `dlkey` |  | DLキー。**個人用カタログだけ**で使う（共用カタログの登録フォームには無い）。DL一覧として書き出すときは、利用者が選んだときだけ入る |

ツールの画面では、`status` を「新旧」と「通常・予備」の2つに分けて見せます。

| `status` | 新旧 | 通常・予備 |
|---|---|---|
| `active` | 新 | 通常 |
| `mirror` | 新 | 予備 |
| `old` | 旧（移転済み） | — |
| `closed` | 終了 | — |

DLに使う順番：利用者が選んだ「デフォルトのDL先」→ `active`（上から）→ `mirror`（上から）→ `old`（上から）。取れなかったら次を試します。`closed` は表示だけにして、DLには使いません。

### 共用カタログと個人用カタログ（DL一覧）

- **共用カタログ**：作者さんが登録フォームから登録した作品の `index.json`。ツールはURLで読み、書き換えません
- **個人用カタログ**：利用者がツールの中で作るカタログ。いくつでも持てて、カタログごとに「候補に含める」を切り替えられます
- **DL一覧**：個人用カタログを人に渡すために書き出したもの。中身は `index.json` と同じ形（`format: 1`）に、次のキーが付きます。受け取った人は「DL一覧を読み込む」で、個人用カタログの1つとして使えます

```json
{ "format": 1, "kind": "cw-catalog/personal", "name": "おすすめ短編集", "exported": "2026-11-01T12:00:00Z", "tool": "CWカタログ 0.2.0", "authors": {}, "entries": [ … ] }
```

同じ作品が複数のカタログに載っているとき（作品名＋作者が同じとき。全角半角・空白・記号の違いは無視）、ツールは1つの作品にまとめ、配布元・紹介ページを合わせて見せます。

### 読む側が守ること

カタログはネットから来るデータなので、信用せずに扱ってください。

- `format` が知らない値なら読まない
- URLは `https://`・`http://` で始まるものだけを使う（`javascript:` などは捨てる）
- 文字列は**文字として**表示する（HTMLとして解釈しない）
- 知らないキーは無視する（将来、項目が増えても壊れないように）

## 2. ツールの記録

ツールの「設定 → 記録 → 書き出す」で出るファイルです。他のツールに手持ちの一覧を渡すときに使えます。

```json
{
  "format": 1,
  "kind": "cw-catalog-tool/records",
  "tool": "0.1.0",
  "exported": "2026-11-01T12:00:00Z",
  "engines": [
    { "id": "eng-abc123", "name": "CardWirthNext 1.60", "kind": "next", "label": "CardWirthNext", "path": "D:\\Games\\CardWirthNext" }
  ],
  "records": [ { … } ]
}
```

`engines[].path` は、アプリ版だけに入ります（HTML版はブラウザの仕組み上、フォルダの場所を持ちません）。

#### records[]（自分のフォルダにある作品1件）

| キー | 説明 |
|---|---|
| `id` | `<エンジンid>:<場所>`（zipの中の場合は `#<中の場所>` が付く） |
| `engineId` | どのエンジンに入っているか（`__mat` は「素材の置き場所」） |
| `type` | `folder`（展開済み）／`archive`（zip・wsnのまま）／`bookmark`（カタログ外の登録）／`material`（素材の置き場所にあるもの）／`skin`（スキンの置き場所にあるもの。`engineId` は `__skin`） |
| `path` | エンジンのフォルダからの場所（例 `Scenario/_店/うさぎ小屋`）。素材は素材の置き場所からの場所（例 `スキン/和風`） |
| `kind` | 素材のとき、`dir`（フォルダ）か `file`（ファイル） |
| `inner` | zipの中の場所（`archive` のとき） |
| `name` `author` | `Summary.wsm`／`Summary.xml` から読んだ作品名・作者 |
| `format` | `classic` `next` `wsn` `unknown` |
| `dataVersion` | クラシック・Nextのデータ版（0・2・4・7） |
| `wsnVersion` | Pyの WSN の版 |
| `encrypted` | Nextの暗号化（WDP）があるか。true／false／null（不明） |
| `version` | 手元の版（利用者が付けたタグ。空なら不明） |
| `versionSource` | `catalog`（ファイル一致で確定）・`dl`（カタログからDLした版）・`user`（手入力）・`guess`（名前から推測）・空 |
| `versionGuess` | フォルダ名などから推測した版 |
| `tags` | 利用者が付けたタグ |
| `note` | メモ |
| `workKey` | 対応するカタログの作品（作品名＋作者をそろえたもの。無ければ空）。0.1.x の `entryId` はこれに置き換わりました |
| `state` | `latest`・`update`・`unknown`・`none`（カタログ外） |
| `sha256` | 入れたときのファイルの SHA-256 |
| `pageUrl` | ブックマークの配布ページ |
| `missing` | 前回の読み取りで見つからなかった |
| `installedAt` `seenAt` `updatedAt` | 日時 |

## 3. シナリオの判定方法

### クラシック／Next：`Summary.wsm`

| 順 | 中身 |
|---|---|
| 1 | 画像（4バイトの長さ＋本体） |
| 2 | 名前（4バイトの長さ＋CP932の文字列） |
| 3 | 説明（同上） |
| 4 | 作者（同上） |
| 5 | 必要クーポン（同上） |
| 6 | 必要クーポン数（4バイト） |
| 7 | 開始エリアID（4バイト）→ **ここでデータ版が分かる** |

数値はリトルエンディアンの符号付き32ビット。文字列の末尾の `\0` は取り除きます。

| 開始エリアID | データ版 | 形式 |
|---|---|---|
| 〜19999 | 0 | classic（古い版） |
| 20000〜39999 | 2 | classic |
| 40000〜49999 | 4 | classic（1.50） |
| 70000〜 | 7 | next（CardWirthNext 1.60） |

（CardWirthPy の `cw/binary/summary.py` と同じ基準です）

### Py：`Summary.xml`

```xml
<Summary dataVersion="5">
  <Property>
    <Name>作品名</Name>
    <Author>作者</Author>
    <Level min="1" max="3"/>
```

`dataVersion` が WSN の版（Wsn.5 なら 5）です。`.wsn` ファイルの中身は zip で、トップに `Summary.xml` があります。

### Nextの暗号化（WDP）

`.wid` ファイルの先頭4バイトが `57 44 50 00`（`WDP\0`）なら暗号化されています。WirthBuilder（Next版）の保存時の初期設定です。`Summary.wsm` は暗号化されないので、判定には復号は不要です。

### シナリオの範囲

- `Summary.wsm` か `Summary.xml` があるフォルダが、シナリオの一番上
- 両方あるときは `Summary.xml`（WSN）を優先
- 入れ子になっていたら外側だけをシナリオとする
- zipの中でシナリオの外にある `.txt` は、作者さんが置いたReadmeの可能性が高い

### 文字コード

| 対象 | 判定の順番 |
|---|---|
| zip内のファイル名 | UTF-8の目印（汎用フラグ bit 11）あり → UTF-8。無ければ UTF-8（厳密）→ CP932。最後に NFC 正規化 |
| Readmeの中身 | BOM → UTF-8（厳密）→ CP932（厳密）→ CP932（化けを承知で） |

Shift_JIS ではなく **CP932**（Windows-31J）で読んでください（①②・髙・﨑 などのため）。

### 版の比べ方

数字のかたまりごとに数値として比べます。`1.10` は `1.9` より新しく、`1.0` と `1.0.0` は同じです。

## 4. ポータブル版の更新情報（latest-portable.json）

リリースに置く、アプリの「更新を確認」が見に行くファイルです（`https://github.com/<リポジトリ>/releases/latest/download/latest-portable.json`）。

```json
{ "version": "0.3.0", "notes": "変更点", "pub_date": "2026-10-24T12:00:00Z",
  "url": "https://github.com/<リポジトリ>/releases/download/v0.3.0/CWCatalog.exe",
  "signature": "（minisign の署名を base64 にしたもの。Tauri の signer で作る）" }
```

アプリは、`url` がこのリポジトリのリリースであることと、`signature` がアプリに埋め込んだ公開鍵（`src-tauri/update-pubkey.txt`）で確かめられることを調べてから、自分自身を入れ替えます。

- format 1（2026-10）：最初の版
