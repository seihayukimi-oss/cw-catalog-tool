# 開発とリリースの手順

CWカタログを直す人・版を出す人向けのメモです。使い方は [README](../README.md) と [はじめに.txt](../package/はじめに.txt) を見てください。

## 開発

```bash
npm ci            # 部品を入れる（.npmrc でインストール時スクリプトは無効）
npm test          # 中核処理の試験（test/core.test.mjs）
npm run build     # dist/web/cw-catalog.html（HTML版）と dist/app/（アプリ版の画面）を作る
npx tauri dev     # アプリ版を開発モードで起動（Rustが必要）
```

実物の作品ファイルを使う試験は、作者さんの作品をリポジトリに入れないために、手元のフォルダを指定したときだけ動きます（指定しないと飛ばされます）：

```bash
CW_FIXTURES=/path/to/fixtures npm test
CW_FIXTURES=/path/to/fixtures node test/e2e.mjs ./shots   # ブラウザでHTML版を動かす試験（Playwright）
```

### フォルダ構成

中身（HTML＋JavaScript）は1つで、器が2つ（アプリ版・HTML版）です。

| 場所 | 中身 |
|---|---|
| `src/core/` | 画面に関係ない中身（zip・cab・lzh・7z の展開、Summary.wsm／Summary.xml の読み取り、文字コード、カタログ、インストール）。HTML版・アプリ版で共通 |
| `src/app/` | 画面 |
| `src/platform/` | 器ごとの違い：`tauri.js`（アプリ版）・`fsa.js`（ブラウザのフォルダ書き込み）・`browser.js`（HTML版） |
| `src-tauri/` | アプリ版（Rust・Tauri 2）：ポータブル版の土台・ネットの読み込み・更新・ダウンロードフォルダ・Windowsへの登録 |
| `package/はじめに.txt` | 配布物に入れる説明 |
| `scripts/make-portable.mjs` | 配布物（zip・latest-portable.json）を作る |
| `scripts/strings/listall.mjs` | 画面の文の一覧を作る |
| `CHANGELOG.md` | 更新履歴（アプリの「設定」のいちばん下にも出る） |
| `docs/データ形式.md` | 公開している仕様（カタログの JSON・ツールの記録・シナリオの判定方法） |

### 決まりごと

- 依存の部品は最小限にし、版を固定します。出てから**2週間以上たった版**だけ使います
- ネットから来た zip・カタログは信用しません（`../` などの危ないパス・異常なサイズは止める、文字は HTML として解釈しない、URL は http・https だけ）
- zip 内のファイル名・テキストは、UTF-8 を先に試し、だめなら CP932 で読みます
- 作者さんの作品ファイル（試験用を含む）はコミットしません

## ワークフロー（GitHub Actions）

| ファイル | 名前 | いつ動くか |
|---|---|---|
| `ci.yml` | テストとHTML版の公開 | `main` に入るたび。HTML版を GitHub Pages に置く |
| `test-build.yml` | お試し版を作る | 手動（Actions →「お試し版を作る」→「Run workflow」）。署名なしの exe |
| `release.yml` | リリース | `v*` のタグを push したとき。下書きのリリースを作る |
| `security-audit.yml` | 部品の安全チェック | 毎週。見つかったら知らせるだけ |

HTML版の公開ページ：https://seihayukimi-oss.github.io/cw-catalog-tool/cw-catalog.html

## 版を出す

版は、運営者がOKするまで **0.x** のままです。正式版が **1.0.0** です。

1. `CHANGELOG.md` に新しい版を書き足す
   - `### 要点`：使う人向けに、短くやさしく
   - `### もっと詳しく`：直したところの一覧
2. 版を上げる：`package.json` と `src-tauri/Cargo.toml`（`package-lock.json`・`src-tauri/Cargo.lock` の自分の版も合わせる）。`tauri.conf.json` は `package.json` の版を見ます
3. `npm test` と `npm run build` が通るのを確かめて、`main` に入れる
4. 運営者に渡すもの：
   - HTML版（`cw-catalog-vX.Y.Z.html`。`dist/web/cw-catalog.html` の名前を変えたもの）
   - ソースの zip（`git archive`）
   - `はじめに.txt`
   - 画面の文の一覧：`node scripts/strings/listall.mjs CWカタログ_画面の文一覧_X.Y.Z.txt`
5. **運営者がOKしてから**、`vX.Y.Z` のタグを付けて push する
6. Actions がポータブル版とHTML版を作り、署名して、**下書き**のリリースに置く
   - `CWCatalog-vX.Y.Z-portable.zip`（CWCatalog.exe・cw-catalog.html・はじめに.txt）
   - `CWCatalog.exe` と `latest-portable.json`（アプリの「更新を確認」が見るもの）
   - `cw-catalog-vX.Y.Z.html`
7. 中身を確かめて、GitHub の画面で「公開」する → アプリの「更新を確認」で新しい版が見つかるようになる

**1.0.0 の前に、0.9.0 → 0.9.1 で自動更新を試します。**

## 更新用の署名鍵

ポータブル版の更新には、**更新用の署名鍵**（無料・自分で作る）が要ります。Windowsのコード署名証明書とは別物です。このリポジトリでは設定済みです。

1. 鍵を作る：`npx tauri signer generate -w ~/.tauri/cwcatalog.key`
2. 公開鍵（`cwcatalog.key.pub` の中身）を `src-tauri/update-pubkey.txt` に入れる
3. GitHub のリポジトリの Settings → Secrets and variables → Actions →「New repository secret」で登録：
   - `TAURI_SIGNING_PRIVATE_KEY`：秘密鍵ファイル（`cwcatalog.key`）の中身
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`：鍵を作ったときのパスワード
4. 秘密鍵はなくさないように保管する（なくすと、それまでのアプリに更新を届けられなくなる）。**チャットやリポジトリには貼りません**

## おすすめの設定（GitHub）

- Settings → Code security：Dependabot alerts と CodeQL（Default setup）を有効にする
- Settings → Code security：Private vulnerability reporting を有効にする（有効にしてあります。[SECURITY.md](../SECURITY.md)）
- Settings → Pages：Source を「GitHub Actions」にする
